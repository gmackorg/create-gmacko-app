Overview

The scaffold today ships apps/nextjs (Next 16, App Router, next-intl, Sentry for Next) talking to a tRPC router in packages/api over Drizzle + postgres-js, with Pino logging and a Node OpenTelemetry SDK. None of that runs cleanly on Cloudflare Workers, and the repo already carries three half-lanes (ForgeGraph VPS, vinext, a stub apps/tanstack-start) to paper over it.

This design collapses the web lane to one runtime and one contract. packages/domain holds Effect Schema models, typed errors, and the HttpApi definition. packages/api implements it as Effect services and handler groups with no framework imports. apps/web (TanStack Start on the Cloudflare Vite plugin) mounts that handler at /api/*, mounts better-auth at /api/auth/*, and renders routes whose loaders call the same contract in-process. Expo, the CLI, and the MCP server consume a derived HttpApiClient. OpenAPI is generated from the contract, retiring the hand-written spec and versioning middleware.

Migration runs in parallel: apps/web is built to parity alongside apps/nextjs, then Next, tRPC, Postgres, and the vinext lane are deleted in the final phase.

Why D1 rather than Postgres via Hyperdrive. ForgeGraph can already provision Postgres for Workers through a tunnel and Hyperdrive, and keeping it would remove roughly a third of this plan. D1 is chosen anyway because it is the database the template's users get for free: no node, no tunnel, no Hyperdrive config, no ForgeGraph dependency to run the web app, one wrangler d1 create per app, and data colocated with the Worker. The costs are accepted and designed for below: no interactive transactions (guarded writes and batch), forward-only migrations with expand/contract, a per-database size ceiling, and a single-region primary. Apps that outgrow those move to Postgres by swapping the Database layer, which is the reason it exists as a layer.
Floor. If the Phase 0 spikes for D1 or Drizzle's Effect D1 driver fail their kill criteria, the plan degrades to a smaller, still-valuable migration: TanStack Start + Effect HttpApi on Postgres via Hyperdrive, keeping today's pg schema, transactions, seed, and migrations.yml. The Database service gets a @effect/sql-pg layer instead of D1, and D1 returns as a Phase 9 option. Every phase after 0 is written so that swap is one layer and one config file.

Effort. The estimates in this plan assume Claude Code does the typing with a human reviewing: roughly 8 weeks elapsed. For a single human author without that, plan on 14 to 16 weeks.

Interface principles

"Very clean" is the requirement, so these are the rules the implementation is reviewed against. Each maps to something concrete in the layout below.

01 · One contract

AppApi in packages/domain is the single source for routes, payloads, errors, and status codes. Server, clients, OpenAPI, and docs are all derived from it. No hand-maintained parallel types.

02 · Framework-free packages

Only apps/web imports TanStack. Only packages/api knows HTTP, and only through HttpApiBuilder. Services take plain inputs and return Effects.

03 · Errors are values with a home

Every failure a client can see is a Schema.TaggedError declared next to its endpoint with its HTTP status. Handlers never construct responses or throw.

04 · Env is a service (in the Worker bundle)

Bindings and secrets enter once, in apps/web/src/server/runtime.ts, as AppConfig and Database layers. No package that ships inside apps/web reads process.env or cloudflare:workers; that covers flags, analytics/web, config/preview, monitoring/web, and the rest. Node-only consumers (the CLI, the MCP server, Expo build scripts) keep their typed env modules. The scope is what makes the no-raw-process-env standard enforceable.

05 · Thin handlers, real services

A handler decodes nothing and validates nothing; it resolves CurrentUser and calls one service method. Business rules live in services (Posts, Workspaces, ApiKeys, LaunchControls, Account).

06 · Same call on both sides of SSR

Route loaders and browser code call the same api.posts.list(). On the server it dispatches in-process; in the browser it goes over fetch. The in-process transport hands the outer request's RequestContext to every dispatch, so six prefetches in one render share one session, role, and membership read. No createServerFn per query.

07 · Auth is declared per endpoint, not sniffed from context

Each endpoint names the credential it accepts: Session (cookie only), SessionOrKey("read"), SessionOrKey("write"), SessionOrKey("admin"), or nothing (public). The Authentication middleware yields CurrentUser plus the credential kind and rejects a key whose scope is too low with a typed 403. Cookie credentials are honoured on non-GET requests only when Origin is on the allowlist. Admin and workspace roles are further middlewares reading a request-scoped cache, never per-handler DB lookups.

08 · Layers are the test seam

Tests provide Database.layer(localD1) or an in-memory SQLite layer and run the real handlers. No mocking of Drizzle, no vi.mock of modules.

09 · Server functions are for cookies and redirects only

createServerFn is allowed for actions that must set a cookie or redirect (sign-out, locale switch). Every read and write of app data goes through AppApi, so there is one place to look for behaviour.

10 · Module scope does no I/O

The runtime and its layers are built at module scope for reuse across requests, so they must construct services without network or DB calls. First-request work happens in the request, under a span.

1 · The contract — packages/domain/src/posts/api.ts 
import { Schema } from "effect"
import { HttpApiEndpoint, HttpApiGroup, HttpApiSchema } from "effect/unstable/httpapi"
import { Session, SessionOrKey } from "../security"   // credential kind + API-key scope, per endpoint

export const PostId = Schema.String.pipe(Schema.brand("PostId"))

export class Post extends Schema.Class<Post>("Post")({
  id: PostId,
  title: Schema.String,
  content: Schema.String,
  createdAt: Schema.Date,
  updatedAt: Schema.NullOr(Schema.Date),
}) {}

export class CreatePost extends Schema.Class<CreatePost>("CreatePost")({
  title: Schema.String.pipe(Schema.minLength(1), Schema.maxLength(256)),
  content: Schema.String.pipe(Schema.maxLength(256)),
}) {}

export class PostNotFound extends Schema.TaggedError<PostNotFound>()(
  "PostNotFound", { id: PostId }, HttpApiSchema.annotations({ status: 404 }),
) {}

export class PostsApi extends HttpApiGroup.make("posts")
  .add(HttpApiEndpoint.get("list", "/").addSuccess(Schema.Array(Post)))
  .add(HttpApiEndpoint.get("byId", "/:id")
        .setPath(Schema.Struct({ id: PostId }))
        .addSuccess(Post).addError(PostNotFound))
  .add(HttpApiEndpoint.post("create", "/")
        .setPayload(CreatePost)
        .addSuccess(Post, { status: 201 })
        .middleware(SessionOrKey("write")))          // cookie session, or a gmk_ key holding "write"
  .add(HttpApiEndpoint.del("remove", "/:id")
        .setPath(Schema.Struct({ id: PostId }))
        .addSuccess(Schema.Void).addError(PostNotFound)
        .middleware(SessionOrKey("delete")))
  // settings.deleteAccount and settings.createApiKey use .middleware(Session) — never reachable with a key
  .prefix("/posts") {}

// packages/domain/src/api.ts
export class AppApi extends HttpApi.make("gmacko")
  .add(AuthApi).add(PostsApi).add(SettingsApi).add(AdminApi)
  .prefix("/api") {}

The same CreatePost class is the TanStack Form validator in the browser (via Schema.standardSchemaV1), the request decoder on the server, and the OpenAPI component. packages/validators and drizzle-zod go away.

2 · A service — packages/api/src/posts/service.ts 
import { Context, Effect, Layer } from "effect"
import { Database, DatabaseError } from "@gmacko/db"
import { post } from "@gmacko/db/schema"
import { CreatePost, Post, PostId, PostNotFound } from "@gmacko/domain/posts"
import type { CurrentUser } from "@gmacko/auth"

export class Posts extends Context.Service<Posts, {
  readonly list: Effect.Effect<ReadonlyArray<Post>, DatabaseError>
  readonly byId: (id: PostId) => Effect.Effect<Post, PostNotFound | DatabaseError>
  readonly create: (input: CreatePost, actor: CurrentUser) => Effect.Effect<Post, DatabaseError>
  readonly remove: (id: PostId, actor: CurrentUser) => Effect.Effect<void, PostNotFound | DatabaseError>
}>()("@gmacko/api/Posts") {
  static layer = Layer.effect(Posts, Effect.gen(function* () {
    const { db, first } = yield* Database       // db: Drizzle's Effect API, already failing with DatabaseError (mapped once, in Database)
    return Posts.of({
      list: db.select().from(post).orderBy(desc(post.createdAt)).limit(10).pipe(
        Effect.flatMap(Schema.decodeUnknown(Schema.Array(Post))),
      ),
      // first(): the row, or the given typed error on zero rows. DatabaseError passes through untouched,
      // so an outage is a 500 with a trace id, never a 404.
      byId: (id) => first(db.select().from(post).where(eq(post.id, id)), () => new PostNotFound({ id })),
      create: (input, actor) => first(db.insert(post).values(input).returning(), () => new InternalError()),
      remove: (id) => ...,
    })
  }))
}

Services never see a Request, a header, or a status code. Their error channel is the exact union the contract promises, so tsc fails if a handler forgets to declare an error the service can produce. No tryPromise, no per-method mapError, no per-method withSpan: the Database service maps SqlError once, and the API layer opens one span per endpoint named group.endpoint. Services add spans only for named sub-steps.

6 · Authentication middleware — packages/auth/src/middleware.ts 
// packages/domain/src/security.ts — declarations only
export class CurrentUser extends Context.Service<CurrentUser, User & { credential: "session" | "key" }>()("@gmacko/CurrentUser") {}

// Cookie session only. Used by deleteAccount, createApiKey, and anything a leaked key must never reach.
export class Session extends HttpApiMiddleware.Tag<Session>()("@gmacko/Session", {
  failure: Unauthorized | Forbidden, provides: CurrentUser,
  // better-auth prefixes the cookie with __Secure- when secure (staging/production); the name comes from AppConfig.stage
  security: { session: HttpApiSecurity.apiKey({ in: "cookie", key: sessionCookieName(stage) }) },
}) {}

// Cookie session, or a gmk_ key whose permissions include `scope` (or "admin").
export const SessionOrKey = (scope: ApiKeyPermission) => class extends HttpApiMiddleware.Tag<...>()(`@gmacko/SessionOrKey/${scope}`, {
  failure: Unauthorized | Forbidden, provides: CurrentUser,
  security: { session: ...cookie..., apiKey: HttpApiSecurity.bearer },
}) {}

// packages/auth/src/middleware.ts — implementation
export const SecurityLive = Layer.effect(..., Effect.gen(function* () {
  const ctx  = yield* RequestContext      // per-request memo: session, role, memberships (one D1 read each, however many API calls the render makes)
  const keys = yield* ApiKeys
  const cfg  = yield* AppConfig
  return {
    session: (req) => Effect.gen(function* () {
      if (req.method !== "GET" && !cfg.allowedOrigins.has(req.headers.origin)) return yield* new Forbidden({ reason: "origin" })
      return { ...(yield* ctx.session), credential: "session" }
    }),
    apiKey: (scope) => (bearer) => keys.authenticate(bearer).pipe(
      Effect.filterOrFail((k) => k.permissions.includes(scope) || k.permissions.includes("admin"), () => new Forbidden({ reason: "scope" })),
      Effect.flatMap((k) => ctx.user(k.userId)),
      Effect.map((u) => ({ ...u, credential: "key" })),
    ),
  }
}))

// AdminOnly and WorkspaceRole("admin") are the same shape, layered on CurrentUser, reading ctx.role / ctx.memberships.

Row-shaped domain models are Model.Class declarations; the json variant is what the contract exposes and the insert variant is what services accept. Every query carries the D1 client's span with the statement as an attribute. Slow-query flagging moves from the Pino logger option to a span attribute threshold. plain exists only because better-auth's adapter is promise-based; nothing in packages/api may use it, enforced by a standards rule.

Auth

  • better-auth stays. makeAuth(config, drizzle) in packages/auth switches the adapter to provider: "sqlite" and drops the module-level db import (the current package hard-imports @gmacko/db/client, which reads process.env at import time and can't exist on Workers).
  • auth-schema.ts is regenerated with @better-auth/cli generate for sqlite; the custom role column is re-added as today.
  • Plugins: oAuthProxy, expo(), magicLink, tanstackStartCookies(). The emulate OAuth overrides (AUTH_GITHUB_URL etc.) flow through AppConfig unchanged.

Alternatives considered

@effect/rpc instead of HttpApi — rejected

Rpc is closer to tRPC ergonomically and supports streaming. But this repo exposes a public REST surface for API keys, ships an OpenAPI SDK, and drives CLI/MCP tools from it. HttpApi gives REST semantics, status-coded errors, and OpenAPI generation for free; Rpc would need a second surface for all of that. Streaming can be added later as a single Rpc group mounted beside the API if realtime needs it.

Pure @effect/sql-d1 (Model + SqlSchema + SqlResolver) instead of Drizzle — fallback

The most Effect-native option: hand-written sql templates decoded by Schema, resolver batching, fewest dependencies. Costs: hand-written SQL migrations with no diffing, no relational query API, and better-auth would need kysely-d1 (with transaction: false and a fake instance for its CLI). Since Drizzle 1.0 rc.4 runs its query builder natively on @effect/sql-d1, we get the Effect-native execution model and keep drizzle-kit and the Drizzle adapter. This option becomes the plan only if the Phase 0 spike finds the rc driver missing batch, returning, or relational queries.

Promise-based drizzle-orm/d1 wrapped in Effect.tryPromise — rejected

The original draft of this plan. Zero new risk, but errors are typed only at the wrapper, there is no SqlClient for raw statements, and Model.Class can't be used. Now that the native integration exists, this is the least clean of the three.

effect-atom instead of TanStack Query — deferred

AtomHttpApi is elegant, but SSR dehydration via @tanstack/react-router-ssr-query already works, and Expo uses Query. Keeping Query removes a whole class of migration risk. Revisit once the API is stable.

Effect 3.x instead of the 4 RC — rejected

v3 is stable today, but v4 stable is targeted for this quarter, no further breaking changes are planned, and this is greenfield code. Building on v3 guarantees a second migration. Mitigation: pin exact RC versions in the pnpm catalog and keep a Phase 0 compatibility spike.

Postgres via Hyperdrive instead of D1 — rejected per request

Would keep the schema unchanged and ForgeGraph's forge db create path. The user chose D1; the cost is the transaction model and a data migration for existing deployments. For new scaffolds there is no data to migrate.

In-place rewrite of apps/nextjs instead of a parallel apps/web — rejected

Parallel build keeps CI green throughout, lets Expo and the operator lane switch on a flag day, and turns the last phase into a deletion instead of a bisect.

Goals & Non-goals

Goals

  • pnpm dev runs the web app on the Workers runtime locally with D1; wrangler deploy ships it.
  • Every one of the 26 current procedures exists as an HttpApi endpoint with feature parity and ported tests.
  • All 10 pages of apps/nextjs exist in apps/web with SSR + hydration.
  • Expo, CLI, and MCP consume @gmacko/api-client and pass their existing tests.
  • OpenAPI spec and docs are generated from the contract; sdks/openapi regenerates from it.
  • No package outside apps/web imports TanStack, Cloudflare, or Node-only modules.
  • pnpm check (lint, typecheck, standards, tests, build) passes with apps/nextjs deleted.
  • The scaffolder generates the new layout and its e2e suite passes.

Non-goals

  • Migrating live production data from Postgres to D1 for any deployed app (a script is out of scope; the template has no production data).
  • Rewriting packages/realtime (BullMQ/Redis). It is Node-only and is marked unsupported on the web lane; Queues/Durable Objects are a follow-up.
  • Enabling i18n routing. The toggle stays off; only the library swap happens.
  • Changing the Expo app beyond the API client swap.
  • Adopting effect-atom or Effect-based forms.
  • Changing ForgeGraph itself. It orchestrates; wrangler deploys.
